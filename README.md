# 직원태양광 등기부등본 확인 자동화

직원태양광 법인들에 분기마다 보내는 **등기부등본 변경사항 확인 메일**을 자동으로 보내고, 회신을 챙기는 Google Apps Script입니다.

담당자가 법인마다 메일을 쓰고 회신 여부를 엑셀로 확인하던 일을 대신합니다. 법인별 등기부등본 PDF를 첨부하고, 회신이 없으면 리마인드를 보내며, 그래도 답이 없으면 담당자에게 알립니다. 회신이 와도 내용이 '변경 없음'으로 확실할 때만 닫고, 그 밖의 회신은 담당자에게 넘깁니다.

## 하는 일

| 시점 | 동작 |
|---|---|
| 분기 발송일 7일 전 | 담당자에게 발송 예정 사전 알림 |
| 분기 발송일 | 법인마다 등기부등본 PDF를 첨부하고 확인 항목 3가지(대표이사 주소 / 임원 구성 / 본점 주소)를 안내하는 메일 발송 |
| [변경사항 없음] 버튼 응답 | 확인 화면에서 [제출]을 누르면 `회신완료` 기록, 담당자에게 알림 |
| 메일 답장이 오면 | 본문(인용 제외)을 읽어 '변경 없음'이 분명하면 `회신완료`, 아니면 `변경확인필요`로 돌리고 담당자에게 회신 내용과 함께 알림 |
| 7일간 회신이 없으면 | 같은 메일 스레드에 등기부등본을 다시 첨부해 리마인드 발송 |
| 리마인드 1일 뒤에도 무응답이면 | 담당자에게 `[조치필요]` 보고 메일 |
| 매 실행 후 | 처리 결과와 확인이 필요한 건을 담당자에게 요약 메일로 보냄 |

매일 오전 9시에 자동으로 실행되며, 새 분기가 되면 지난 분기 기록을 비우고 다음 발송을 준비합니다.

### 상태 흐름

```
(대기) ─▶ 발송중 ─▶ 발송완료 ─┬─▶ 회신완료                (버튼 응답 / '변경 없음' 메일 회신)
                              ├─▶ 변경확인필요 ─▶ 회신완료  (담당자가 대시보드에서 [처리완료])
                              ├─▶ 발송실패                 (반송)
                              └─▶ 리마인드발송 ─▶ (회신 시 위와 같음 / 무응답이면 [조치필요] 보고)
```

- `발송중`은 메일을 보내기 **직전에** 먼저 기록합니다. 보낸 뒤 기록하다 끊기면 다음 실행이 보낸편지함과 대조해 기록만 채우고, 실제로 안 나갔으면 다시 보냅니다.
- `변경확인필요`는 분기가 바뀌어도 초기화하지 않습니다. 담당자가 처리할 때까지 그 법인의 다음 분기 메일은 보류되고 요약 메일로 계속 알립니다.
- 등기 변경이 확인되면 새 등기부등본을 발급해 드라이브의 `등기부등본_법인명.pdf`를 교체합니다. 변경이 없으면 기존 파일을 계속 보냅니다.

## 구성

| 구분 | 내용 |
|---|---|
| 코드 | `AppsScript/*.js` (구글 시트에 연결된 Apps Script, V8). 아래 파일 구성 참고 |
| 구글 시트 | `법인목록`(법인별 수신자·발송 상태 등), `로그`(처리 이력, 대시보드 열람·거부 기록 포함) |
| Gmail | 처음 메일은 GmailApp, 리마인드는 Gmail API(고급 서비스)로 원래 스레드에 이어 보냄 |
| 구글 드라이브 | 법인별 등기부등본 PDF 폴더. 파일 이름은 `등기부등본_법인명.pdf` |
| 웹앱 | [변경사항 없음] 버튼의 응답 화면, 담당자용 현황 대시보드 |
| 테스트 | `tests/local-test.js` 모의 환경 시나리오 테스트 (`node tests/local-test.js`) |

- 상태 값: (빈칸=대기) / 발송중 / 발송완료 / 리마인드발송 / 회신완료 / 변경확인필요 / 발송실패
- 응답유형 값: 변동없음(버튼) / 변동없음(메일) / 확인필요 / 변경처리완료
- 변경내용: 확인이 필요한 회신의 본문 발췌(인용 제외)가 자동으로 들어갑니다
- 응답토큰, 응답유형 등은 스크립트가 채웁니다

## 설정: 스크립트 속성

이름·이메일·주소와 대시보드 키는 **코드에 적지 않고** 편집기의 "프로젝트 설정 > 스크립트 속성"에 넣습니다. 서명·연락처 값이 하나라도 비어 있으면 자동 실행이 **메일을 보내지 않고** 담당자에게 알림만 보냅니다.

| 속성 | 용도 |
|---|---|
| `STAFF_NAME`, `STAFF_TITLE`, `STAFF_EMAIL` | 담당자 이름·직책·이메일 (메일 서명, 알림 수신) |
| `MANAGER_NAME`, `MANAGER_TITLE`, `MANAGER_EMAIL` | 사수 이름·직책·이메일 (메일 하단 연락처) |
| `OFFICE_ADDRESS` | 본사 주소 (메일 하단) |
| `SENDER_NAME` | 보낸 사람 표시 이름 |
| `DASHBOARD_USERS` | 대시보드 사용자별 키와 역할(JSON). 키는 16자 이상 무작위 문자열 |
| `DASHBOARD_KEY` | (예전 방식) 하나뿐인 키. 있으면 '관리' 권한 1명으로 취급 |

`DASHBOARD_USERS` 예시:

```json
[
  {"key": "무작위-문자열-16자-이상", "name": "담당자", "role": "관리"},
  {"key": "다른-무작위-문자열-16자-이상", "name": "조회자", "role": "조회"}
]
```

| 역할 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 관리 | 전체 현황, 수신자 이름, 회신 내용, 로그 상세 | 변경확인필요 [처리완료] |
| 조회 | 전체 현황(수신자 이름 가림), 로그는 항목만 | 보기만 |

대시보드 주소는 `웹앱 주소?key=본인 키`입니다. 사람을 빼려면 그 사람 항목만 지우면 됩니다.

그 밖의 설정(리마인드 대기 일수, 발송 주기, 실행 시간 한도, 등기부등본 폴더 ID 등)은 `00_Config.js`의 `CONFIG`에 있습니다.

## 실행 목록의 함수

| 함수 | 발송 여부 | 하는 일 |
|---|---|---|
| `발송전_점검` | 없음 | 위 '발송 전 점검' 항목을 점검해 결과를 본인 메일로 보냄 |
| `처음메일_초안_미리보기` | 없음 | 처음 메일을 본인 앞 임시보관함 초안으로 1통 만듦 |
| `리마인드_초안_만들기` | 없음 | 리마인드 대상마다 답장 초안을 만듦(확인 후 삭제) |
| `사전알림_미리보기` | 없음 | 분기 사전 알림 내용을 실행 로그로 확인 |
| `재알림_따라잡기` | **있음** | 매일 자동 실행을 지금 한 번 돌림 |
| `트리거_켜기` / `트리거_점검` | - | 매일 오전 9시 자동 실행 트리거 생성(중복이면 1개로 정리) / 개수 확인 |

이름이 `_`로 끝나는 함수는 내부용이라 실행 목록에 나오지 않습니다.

## 테스트

```
node tests/local-test.js
```

Apps Script 서비스(시트·Gmail·드라이브·잠금 등)를 흉내 낸 모의 환경에서 실제 코드를 그대로 불러와 시나리오를 확인합니다. 실제 메일이나 시트는 건드리지 않습니다.

- 회신 본문 판정 (변경 없음 / 변경 언급 / 애매한 답장 / 첨부 / 인용 잘라내기)
- 첫 발송, 발송 후 기록 실패 → 다음 실행에서 재발송 없이 복구, 실제로 안 나간 발송중 → 재발송
- 메일 회신 변경 없음 → 회신완료, 변경 언급 → 변경확인필요 + 담당자 알림
- 대시보드: 키 없음/틀린 키 거부와 기록, 관리/조회 표시 차이, 조회 권한의 처리완료 서버 거부
- 리마인드 중복 방지, 변경확인 미처리 시 다음 분기 발송 보류, 버튼 응답이 변경확인필요를 덮어쓰지 않음

## 주의
